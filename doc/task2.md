# 战斗表现控制与战斗亚比模型替换设计方案

> 历史设计（2026-08-21），保留以下原始证据和候选思路；旧字段、实施步骤及“仅屏蔽攻击者动作”的范围不作为当前实现指令。2026-09-05 的当前契约见 [Battle](modules/BATTLE_SPEC.md)、[资源管线](modules/RESOURCE_PIPELINE_SPEC.md) 和 [周更手册](runbooks/PETFIGHTNEW_WEEKLY_UPDATE.md)。

## 当前实现与原方案差异（2026-09-05）

- 当前设置为 Battle Version 6：`HideDamageNumbers`、`HideHealingNumbers`、`SkipBattlePresentation`、`BattleMorphEnabled` 和 `MorphRules[{Note,SourceViewId,TargetViewId}]`。
- `SkipBattlePresentation` 跳过每回合演出，不再等同于仅跳过攻击者动作；当前桥 Version 4 使用 16 个白名单方法补丁，保留状态结算和终端回调，不修改全局技能特效或画质选项。
- 战斗模型独立于背包规则；仅支持源/目标 ID 均不小于 4445、不同且位数相同的位图模型。目标双方六分片预检全部通过才可启用；失败保留现有规则，未启用时使用官方资源。桥确认 `active=false` 且 `ended=false` 才切换，无法确认则等待重启。
- 当前生产资源版本为 `2026090340574444`，本地演出候选已静态验证并接入生产清单，但新的真实 Flash 演出及完整模型动作验收仍未完成。

以下章节是历史设计正文。

## 一、需求范围

新增三项互相独立的功能：

1. 隐藏战斗伤害数字。
2. 屏蔽亚比出手动作。
3. 战斗亚比模型替换，替换范围包含待机、出手、受击、登场、死亡等模型动画。

不修改战斗协议数据，不丢弃服务端命令，不影响血量、技能、死亡判定和回合推进。

## 三、设置界面设计

在“形态变化”窗口新增“战斗表现”区域。

全局选项：

- `隐藏伤害数字`
- `隐藏治疗数字`
- `屏蔽亚比出手动作`
- `屏蔽技能特效`
- `启用战斗模型替换`

战斗模型规则字段：

- 备注
- 战斗模型源 ID
- 战斗模型目标 ID
- 生效范围：己方／敌方／双方
- 启用

战斗模型规则应与背包模型替换规则分开保存。可以额外提供“沿用背包模型目标”快捷选项，但内部仍转换成独立的战斗模型规则。

配置默认全部关闭，避免改变现有行为。

## 四、隐藏伤害数字

### 实现位置

修改当前 `petfightnew` 战斗表现层中消费 `HurtInfo`、创建伤害数字 MovieClip 的位置。

处理流程保持为：

```text
接收2411
  → 更新战斗状态和HP
  → 处理受击/死亡
  → 根据设置决定是否创建飘字
  → 正常执行完成回调
  → 继续下一条战斗命令
```

### 规则

- `hpInc < 0`：受“隐藏伤害数字”控制。
- `hpInc > 0`：受“隐藏治疗数字”控制。
- 多段伤害 `hpIncList` 中的每个数字都应被屏蔽。
- 默认保留暴击、闪避、免疫等状态文字。
- 以后如有需要，再单独增加“隐藏战斗状态文字”。

即使不创建飘字，也必须立即调用原来的显示完成回调。不能仅把飘字透明化，因为透明对象的补间和等待时间仍可能拖慢回合。

## 五、屏蔽亚比出手动作

模型动作类型已经确认包含：

- `Stand`
- `PhysicalAtk`
- `SpecialAtk`
- `AttributeAtk`
- `Hurt`
- `CriHurt`
- `Miss`
- `Appear`
- `Die`
- `ExtAction<N>`

启用“屏蔽亚比出手动作”时：

- 拦截 `PhysicalAtk`、`SpecialAtk`、`AttributeAtk`。
- 攻击者保持或立即恢复 `Stand`。
- 必须执行原动画结束回调，让战斗命令队列继续。
- 默认保留目标的受击、暴击受击、死亡、登场和切换动作。
- 不直接停止 MovieClip，也不删除正在播放的对象。

项目已有 `isDebugSkipFightMv` 和 `isHideFightSomething` 运行时开关。实施前应在当前 `petfightnew~2026082009519118.swf` 中定位它们的真实调用点：

- 如果 `isDebugSkipFightMv` 已包含完整的跳过动画及完成回调逻辑，优先复用。
- 如果它会跳过过多内容或未正确完成命令，则只在动作调度器中添加上述三个攻击动作的快速完成分支。

“技能特效”与“亚比出手动作”必须分开控制。技能特效可映射到现有：

`fightSkillEffect = NoFightSkillEffect（值 2）`

## 六、战斗模型替换

### 拦截边界

在 `AolaDynamicRequestHandler` 中仅拦截：

`/play/fightassets/bitmap/pet<ID>/pet<ID>_<方向>_<分片>~<版本>.swf`

不要替换 `play.swf`、`petfightnew.swf` 或其他战斗核心模块。

对规则 `6000 → 6047`，把下列请求映射到 6047 对应资源：

```text
pet6000_2_0 → pet6047_2_0
pet6000_2_1 → pet6047_2_1
pet6000_2_2 → pet6047_2_2
```

方向编号必须原样保留。另一阵营请求 `_1_*` 时同样处理，不能固定使用 `_2_*`。

### 版本处理

不能把源资源的 `~1210` 直接套给目标模型。目标资源版本必须从游戏当前版本数据或真实请求中取得。

目标 6047 的背包头像存在，不代表 6047 的战斗模型资源必然完整。激活规则前必须确认目标模型的全部战斗分片都能取得。

### 类契约适配

战斗调用方会按源 ID 查找类似以下类：

- `mmo.petfight.bitmap.Pet6000Config_1`
- `mmo.petfight.bitmap.Pet6000Config_2`
- 对应的模型和时间轴类

目标 SWF 内通常导出 `Pet6047...` 类。直接返回 6047 SWF 可能导致源类查找失败。

响应适配器应将目标资源的导出类适配成调用方期望的源类契约：

```text
Pet6047Config_1 → Pet6000Config_1
Pet6047Config_2 → Pet6000Config_2
目标模型相关类前缀 → 源模型对应类前缀
```

必须基于 ABC、SymbolClass 和导出类结构进行验证。只有在长度相同且唯一命中等前提完全成立时，才允许最小二进制替换；不能盲目全局替换字符串。

保留目标模型内部的动作时间轴，因此替换后自然使用 6047 的：

- 待机
- 物攻
- 特攻
- 属性攻击
- 受击
- 暴击受击
- 闪避
- 登场
- 死亡
- 扩展动作

技能光效仍按技能 ID 加载，不随模型 ID 替换。此次“包括出手以及动画”定义为替换亚比模型自身的动作，不包含技能特效资源重映射。

### 原子启用与回退

一条模型规则只有在所需方向和全部分片均通过检查后才能启用。

以下任一情况发生时，整条规则回退到原模型：

- 目标文件不存在或返回非成功状态。
- 缺少任意分片。
- SWF 压缩、声明长度或解压长度无效。
- 必需导出类不存在。
- 动作契约不完整。
- 类名适配失败。
- 加载或实例化异常。

严禁出现部分分片为 6000、部分分片为 6047 的混合模型。

## 七、宿主与战斗模块通信

不要依赖背包模块作为桥接，因为玩家可能未打开背包。

建议由当前战斗模块注册独立的 `ExternalInterface` 接口，例如：

- `aolaBattleBridgeReady`
- `aolaBattleApplyOptions(json)`

宿主在以下时间推送设置：

- 战斗模块注册完成时。
- 设置发生变化时。
- 新战斗开始时。

建议传递结构：

```json
{
  "hideDamageNumbers": true,
  "hideHealingNumbers": false,
  "skipPetAttackActions": true,
  "fightSkillEffect": 2
}
```

模型 ID 映射由 HTTP 资源拦截层处理，不需要传入 SWF。

## 九、验收标准

必须在真实 Flash 运行环境中验证，FFDec 能重新读取或项目能编译不等于运行成功。

测试矩阵：

1. 所有功能关闭：行为与修改前完全一致。
2. 隐藏伤害开启：伤害数字消失，但血条、死亡和回合结果不变。
3. 隐藏治疗关闭：治疗数字仍显示。
4. 多段技能：所有伤害分段均不显示，回合正常推进。
5. 屏蔽出手动作：攻击者保持待机，目标仍正常受击或死亡。
6. 技能特效关闭：只关闭技能光效，不改变模型动作。
7. `6000 → 6047`：
   - 待机正常。
   - 物攻、特攻、属性攻击正常。
   - 受击、暴击受击、闪避、登场、死亡正常。
   - 己方和敌方方向均不镜像错误。
8. 切换亚比、后备亚比登场、新战斗均正确。
9. 目标资源缺失或损坏：完整回退到 6000，不允许混合分片。
10. 关闭替换后恢复原模型。
11. 页面刷新及全新进程后再次测试，排除 CEF、Flash Loader 和 ApplicationDomain 缓存影响。
